### Task 1: Soft Link vs. Hard Link

#### Overview & Differences
| Feature | Soft Link (Symbolic Link) | Hard Link |
| :--- | :--- | :--- |
| **Inode** | Has a separate, distinct inode number | Shares the exact same inode as target file |
| **Target** | Points to file path/location | Points directly to physical disk data blocks |
| **Deletion of Original** | Link breaks (becomes dangling) | Content remains accessible via hard link |
| **Cross-Filesystem** | Works across different filesystems | Restricted to the same filesystem |
| **Directories** | Can link directories | Cannot link directories |

#### Commands
```bash
# Create target file
echo "Hello DevOps" > original.txt

# Create Soft Link
ln -s original.txt soft_link.txt

# Create Hard Link
ln original.txt hard_link.txt

# View inodes and file details
ls -li original.txt soft_link.txt hard_link.txt
```

### Task 2: `adduser` vs. `useradd`

#### Comparison & Recommendation
- **`useradd`**: Native, low-level binary command across all standard Linux distributions. It creates a user account without interactive prompts, home directory creation, or default shell assignment unless explicit flags (`-m`, `-s /bin/bash`) are passed.
- **`adduser`**: High-level Perl script wrapper available on Debian/Ubuntu systems. It provides an interactive prompt that automatically creates home directories, copies skeleton configuration files, prompts for password, and sets user details.

> **Recommendation**: On Ubuntu/Debian systems, `adduser` is preferred for interactive administrator user creation, while `useradd` is standard for automation scripts and non-Debian distributions.

#### Practice Command
```bash
# Recommended command on Linux (Ubuntu/Debian)
sudo adduser devops_user

# Native command on macOS (without Docker)
sudo sysadminctl -addUser devops_user -fullName "DevOps User"
```

### Task 3: System Logging with `journalctl`

#### Overview
`journalctl` is the command-line utility used to query and view logs generated by `systemd-journald` service manager.

#### Essential `journalctl` Commands
```bash
# View all system logs
journalctl

# View logs in real-time (follow log output)
journalctl -f

# View logs for a specific systemd service (e.g., nginx or sshd)
journalctl -u nginx

# View logs since current boot
journalctl -b

# Filter logs by priority (e.g., error level)
journalctl -p err
```

### Task 4: Essential Linux Commands Cheat Sheet

#### Key Commands Summary
- `ls -la`: List all files with detailed attributes including hidden files.
- `chmod`: Modify file permission bits (e.g., `chmod +x script.sh`).
- `chown`: Change user and group ownership of files/directories.
- `grep -rn "pattern" .`: Recursively search files for specified string pattern.
- `find . -name "*.log"`: Search file system tree for files matching criteria.
- `top` / `htop`: Real-time system monitoring of CPU, RAM, and running tasks.
